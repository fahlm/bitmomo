# Public Pro Proof-First Remediation

Parent authority: #181. Focused blocker: #183.

## Canonical visitor hierarchy
1. Hero / Founding identity + conversion action.
2. One real delayed/frozen historical Decision View, when eligible.
3. Expected Range visual with BTC reference and settled +24h outcome markers when valid.
4. Bear / Base / Bull scenario map from the same frozen proof row.
5. Explicit thesis invalidation.
6. Product explanation / Free -> Pro boundary.
7. Accountability, Founding economics, whitelist, FAQ.

## Data boundary
Public Pro proof reads only `Bitmomo_Btc_Intelligence_Accountability::delayed_proof(1)`. It never reads the current protected Pro brief. No scenario probability is invented. If eligible historical proof is absent, the page fails closed and explicitly states that Bitmomo does not fabricate demo values.

## Architecture
The behavior is implemented directly in `Bitmomo_Pro_Sales` and its canonical stylesheet. The preserved #176 shortcode-output rewriter is intentionally not used.

## Validation
`test-bitmomo-pro-proof-first-contract.php` locks render order, delayed-only data ownership, range/scenario field provenance, invalidation, fail-closed behavior, absence of the legacy output rewriter, and mobile wrapping/collapse contracts.
